# ボイスアラーム (voice-alarm-app)

自分で使用するための、個人的にほしい機能を詰めた Android 用アラームアプリです。
公開・ストアリリースは前提としていません。

- パッケージ名: `jp.personal.voicealarm`
- 言語: Kotlin / UI: Jetpack Compose (Material3)
- minSdk 26 / targetSdk・compileSdk 34
- データ保存: Room（アラーム／グループ／カスタム休日）

> **重要（ビルドについて）**
> このプロジェクトを作成した環境には Java / Android SDK が入っていないため、
> **この環境ではコンパイル確認を行っていません。** 初回ビルドは Android Studio 上で
> 行い、エラーが出た場合はその内容に合わせて修正してください。
> 想定バージョンは Android Gradle Plugin 8.5.2 / Kotlin 1.9.24 / Gradle 8.14.6 です。
> Gradle Wrapper の `gradle-wrapper.jar` と `gradlew` / `gradlew.bat` は含まれていないため、
> Android Studio で開く際に自動生成されるか、`gradle wrapper --gradle-version 8.14.6` で生成してください。
>
> **Gradle を動かす JDK は Daemon JVM criteria で固定しています。**
> `gradle/gradle-daemon-jvm.properties` に `toolchainVersion=21` と書いてあり、
> JAVA_HOME や IDE の Gradle JDK 指定より優先して、条件に合う Java 21 を自動検出します
> （ベンダーは不問）。フォルダを新しく開き直しても JDK 構成ダイアログは出ない想定です。
> ローカルで見つからない場合は `settings.gradle.kts` の foojay プラグイン経由で
> JDK を自動取得します。やめたい場合はこのファイルとプラグイン行を消せば元に戻ります。

## 実装されている機能（仕様書 v1 対応）

| 機能 | 実装 |
|---|---|
| アラーム複数登録・編集・削除・オン/オフ | 一覧画面＋編集画面、Room 保存 |
| 繰り返し曜日・ラベル | 編集画面（曜日未選択＝1回だけ） |
| ボイス＋SE | 鳴動時に TTS（日本語）で**時刻だけ**を「7時00分です」と読み上げ → SE 再生、このセットを繰り返す |
| 定時＋休日 | 日本の祝日（振替休日・国民の休日含む）はルール計算で自動オフ＋自分で登録するカスタム休日もオフ（両方、グループ単位で切替） |
| グループ化 | グループ管理画面で CRUD、祝日オフ／カスタム休日オフを一括適用 |
| 次回プレビュー | 一覧の各行に、休日・次回スキップを考慮した実際の次回日時を表示 |
| ウィジェット | ホーム画面に最も近い次回アラーム日時を表示（両サイズとも「日にち／時間」の二段表示で時間大きめ。日にち書式は通常＝○月○日、小＝MM/DD）。**ウィジェットにも「次回をスキップ」ボタンあり**（表示中の次回の日付をスキップ予約に追加し、表示はその次のアラームに切り替わる）。本体タップでアプリを開く。誤連打防止あり：スキップ直後3秒以内の連続タップは無視されるため、1回タップしたつもりが表示切替前の誤操作で別のアラームまでスキップされることはない。意図的に続けてスキップしたい場合は、表示が更新されてからもう一度タップする |
| テスト再生 | 編集画面から実際の鳴動画面をテストモードで開き、編集中の音設定のままボイス→SE を確認できる（画面には「テスト再生中」と表示。停止／スヌーズはテスト終了として働き、本物のアラームには影響しない） |
| 次回スキップ | 一覧のボタンとウィジェットのボタンの両方から可能。**日付指定式**：1回の操作で表示中の次回1回分の日付を予約に追加する。表示が更新された後にもう一度押せば、その次の日も追加できるため、**同じアラームの複数日分（例：月曜と火曜）も続けてスキップできる**。スキップした日以外は通常通り鳴る。一覧では「〇回分スキップ中（日付）」と表示され、未来のスキップ予約を全て取り消すボタンもある |
| 音の設定 | SE 選択（端末の TYPE_ALARM 音源一覧から）、ボイス／SE 音量を個別に設定、フェードイン、バイブレーション有無 |
| スヌーズ | アラームごとに分単位で設定（デフォルト5分）。再鳴動時に時刻を読み直す |
| 前夜確認通知 | **なし**（仕様通り。確認はウィジェットで行う） |
| 信頼性 | 再起動・時刻/タイムゾーン変更・アプリ更新後に全アラームを再スケジュール、TTS 失敗時は SE のみにフォールバック、10分で自動停止、ロック画面上に鳴動画面を表示 |

## Android Studio での開き方・ビルド・実行

1. Android Studio (Hedgehog 以降推奨) で `File > Open` からこのフォルダを開く
2. Gradle Sync が終わるのを待つ（初回は依存関係のダウンロードで時間がかかります）
3. 実機を USB デバッグで接続するか、エミュレータを用意する
4. `Run > Run 'app'` でインストール・起動する
5. 署名付き APK が必要なら `Build > Generate Signed Bundle / APK` から作成する

## 初回に必ず行う設定（許可）

アラームを確実に鳴らすために、アプリ内の「設定・許可」画面から次を確認してください。

1. **正確なアラームの許可**
   - Android 12 以降で必要です。未許可だと `setAlarmClock` が使えず、鳴動がずれる場合があります。
   - 本アプリは `USE_EXACT_ALARM`（アラーム用途向け、インストール時に付与）と
     `SCHEDULE_EXACT_ALARM`（ユーザーが許可する方式）の両方を宣言しています。
     端末・OS によって付与状況が異なるため、設定画面で状態を確認してください。
2. **電池の最適化の除外**
   - 最適化対象のままだと Doze 等で鳴らない・遅れる原因になります。設定画面から除外をリクエストできます。
3. **通知の許可（Android 13 以降）**
   - 初回起動時にダイアログが出ます。フルスクリーン通知で鳴動画面を出すために許可してください。

## 祝日計算の範囲 (`HolidayCalculator`)

- 固定日＋ハッピーマンデー＋春分・秋分（近似式）による**ルールベース計算**です（小さな固定リストではありません）
- 振替休日（祝日が日曜の場合に直後の非祝日へ）と国民の休日（祝日に挟まれた平日）も計算します
- 主な対象は **2025〜2027 年**。ユニットテストで 2025 年の黄金週・振替、2026 年 9 月の国民の休日などを確認しています
- 対象外: 皇室行事などその年限定の特別な祝日、五輪などによる祝日移動の特例

## 次回日時の計算ルール (`NextAlarmCalculator`)

候補日を1日ずつ進め、次の順序で判定します（仕様書通り）。

1. 繰り返し曜日に含まれるか
2. グループの祝日オフが有効で、日本の祝日ならスキップ
3. グループのカスタム休日オフが有効で、登録済み休日ならスキップ
4. 候補日がそのアラームのスキップ予約日（`skipDatesCsv`）に含まれていればスキップ（複数日可）

一覧プレビュー・ウィジェット・実際のスケジュール登録はすべて同じ計算を使います。

## プロジェクト構成

```
app/src/main/java/jp/personal/voicealarm/
  MainActivity.kt            画面遷移と Compose の入口
  VoiceAlarmApplication.kt   通知チャンネル初期化
  data/                      Room エンティティ / DAO / DB
  logic/                     HolidayCalculator / NextAlarmCalculator（純粋ロジック）
  scheduler/                 AlarmScheduler（setAlarmClock 等）
  receiver/                  AlarmReceiver / BootReceiver
  ringing/                   RingingService / RingingActivity / VoiceAlarmPlayer(TTS+SE)
  ui/                        一覧・編集・グループ・休日・設定 画面
  viewmodel/                 AlarmViewModel
  widget/                    VoiceAlarmWidgetProvider（RemoteViews）
app/src/test/                HolidayCalculator / NextAlarmCalculator の JUnit テスト
```

保存方式について: アラーム等の構造化データは検索・関連（グループ）があるため
DataStore ではなく **Room** を採用しました（DataStore は単純な設定値向きのため）。

## 未決定事項（仕様書 v1 のまま残しているもの）

- ボイス繰り返し1セットあたりの SE 再生秒数（現実装は暫定 15 秒: `VoiceAlarmPlayer.SE_DURATION_MS`）
- スヌーズの上限回数（現実装は上限なし。自動停止10分が上限の代わり）
- 祝日データの更新方法（現実装はルール計算のみ。法改正時はコード改修が必要）
- 対象端末の最終確認（開発者の実機での許可まわり・TTS 音声の確認が必要）
- グループ設定とアラーム個別設定の優先関係（現実装はグループ設定のみで判定）
- 出勤日例外（祝日でも鳴らす日）は検討事項のままで、v1 には含めていません

## UI テーマ（v1.1）

- アプリ共通テーマ `ui/theme/`（VoiceAlarmTheme）を導入。端末のダークモードに追従し、
  Android 12+ ではダイナミックカラーを優先、非対応環境では「夜明けインディゴ＋アンバー」の標準色を使う
- 一覧画面を再設計：上部はアプリバー＋アイコン操作（グループ／休日／設定）、
  先頭に「次のアラーム」サマリーカード、アラームカードに繰り返し要約（平日／毎日／曜日）と
  オフ状態のグレーアウト、グループ内は時刻順に表示
- 鳴動画面を再設計：アラームのラベルと日付・曜日を表示し、時刻は特大（96sp）表示。
  背景はテーマ色の夜明けグラデーション。ボタンは「○分間スヌーズ」（64dp）と
  「停止」（76dp・プライマリ色）に大きさと色の差を付け、スヌーズ再鳴動時は
  「スヌーズ中」のピルを表示する。表示用の情報は RingingService が Intent で渡す
- 鳴動画面のボタンサイズをボタンごとに設定可能にした：「設定・許可」画面の
  「鳴動画面のボタン」でスヌーズ／停止それぞれ小(56)・中(64)・大(80)・特大(96)・
  巨大(128)・超大(160)・最大(192)から選べる（両ボタン最大で画面の高さの約半分を占める。
  アプリ全体設定として SharedPreferences に保存、次回鳴動から反映。
  既定はスヌーズ=中・停止=大で従来の見た目相当。
  なお小さい画面で時刻表示が潰れないよう、実際の高さは画面の高さの42%が上限）
- 端末の戻るボタンは、一覧以外の画面（編集／グループ／休日／設定）では
  アプリを閉じずトップ（一覧）に戻る
- 編集画面の「テスト再生」「保存」は画面下部のバーに固定し、スクロール位置に
  よらず常に表示する（削除ボタンは誤操作防止のため従来通り本文の末尾）
- 編集画面の本文をセクションカードに整理：「時刻」、「繰り返し・グループ」、
  「音」（SE・音量・フェードイン・バイブ）、「スヌーズ」の4カードに
  見出し付きでまとめた。時刻の入力はダイヤル式ピッカーをやめ、当初は
  時・分のテンキー入力（数値フィールド）にしたが、その後アプリ内の専用
  数字キーパッドに変更：xx:xx 表示に「HHMM」の4桁を左から順に入力する方式
  （桁ごとの範囲チェックで25時・60分は入力不可。4桁揃った状態で数字を押すと
  最初から入力し直し、未入力の桁は薄い0で表示、途中までの入力は右を0で
  埋めて解釈。Cキーで全消去、⌫で1桁戻る）。キーパッドは常時表示ではなく、
  時刻カードの「選択」ボタンから開くメニュー（ダイアログ）の中にあり、
  下書きを編集して「決定」で確定する（繰り返し・音源と同じ方式に統一）
- ボタンの長押し設定：「設定・許可」画面で「停止は長押しで止める」と
  「スヌーズも長押しにする」を個別にオンにでき、オンにしたボタンは長押しでのみ
  効くようになる（押している間は進捗が満ちていく表示。途中で離すと効かない）。
  長押しの時間は停止・スヌーズそれぞれ個別に1秒／2秒／3秒から選べる
- ウィジェットの見た目を設定可能にした：「設定・許可」画面の「ウィジェット」で
  背景色（ホワイト／ブラック／グレー／インディゴ／アンバー／ティール）、
  角丸（なし／小8／中16／大24／特大32dp）、背景の不透明度（20〜100%、10%刻み）を
  変更でき、即ウィジェットに反映される。文字色は背景色に合わせて自動切替。
  背景は実サイズに合わせて画像として描画する方式（RemoteViews の制約のため）。
  スキップボタンも自作のピル型にし、濃さが背景の不透明度に連動する
  （背景を透かすとボタンも一緒に透ける）。ボタンの文字は「SKIP」のみ
- ウィジェットに小さいサイズを追加：ウィジェット一覧に
  「ボイスアラーム（小）」として並ぶ。当初は横長2×1で日時1行表示だったが、
  日時二段表示に合わせて2×2に変更（左に日にち「11/24(火)」／時間「7:00」の
  二段＋ラベル、右にSKIP）。外観設定（色・角丸・不透明度）と更新処理は
  通常サイズと共通
- 一覧のカードをコンパクト化：アラームカードとサマリーカードの余白・行間・
  ボタンを詰め、時刻も一段小さくして、1画面に表示できる件数を増やした
- アラームの複製を追加：編集画面の「このアラームを複製」で、編集中の内容を
  新規アラームとして保存できる（ラベルに「 のコピー」が付き、スキップ予約は引き継がない）
- グループ一括オン/オフを追加：一覧のグループ見出しのスイッチで、その
  セクション内の全アラームをまとめてオン/オフできる（一部だけオンのときは
  スイッチはオフ表示で、押すと全てオンになる）
- スヌーズ上限回数を追加：アラームごとに「スヌーズ最大回数（0=無制限）」を
  設定でき、上限に達すると鳴動画面にスヌーズが出なくなる。回数はスヌーズの
  予約インテントに載せて数える（DB v3、Migration で列追加のみ・既存データ保持）
- 音量ボタンで停止する設定を追加：「設定・許可」画面でオンにすると、鳴動画面の
  表示中は音量ボタン（上下どちらでも）でアラームを止められる
  （その後、動作は「なし／停止／スヌーズ」の3択に変更。旧設定でオンだった
  場合は「停止」として引き継がれる）
- 権限の警告バナー：正確なアラーム／電池の最適化の除外／通知／全画面表示 の
  いずれかが外れていると、アラーム一覧の上部に警告バナー（対象の許可名を明示）
  が出る。タップで設定・許可画面へ遷移。許可チェックは util/PermissionChecks に
  共通化し、設定画面と共用。一覧では画面復帰（ON_RESUME）のたびに再チェックする
- 鳴動時の音量ブースト：鳴動開始時に端末のアラーム音量がアプリ側の設定音量
  （ボイス/SEの大きい方）より小さい場合、鳴動中だけ端末音量を最大まで引き上げる
  （アプリ側の音量は端末音量への掛け算なので、端末側がゼロだと無音になる対策）。
  鳴動が全て終わる（待ち行列も空になる）と引き上げ前の音量に自動で戻す。
  スヌーズ待ちの間はいったん元に戻り、再鳴動でまた引き上げる。編集画面の
  テスト再生（サービスを経由しない）には適用されない
- フルスクリーン許可の確認を追加：「設定・許可」画面で Android 14以降の
  「鳴動画面の全画面表示」の許可状態を表示し、未許可なら許可画面へ直接遷移できる
  （未許可だとロック画面に通知しか出ず、鳴動画面が開かないことがある）
- 同時刻アラームの取りこぼし対策：鳴動中に別のアラームの時刻が来たら待ち行列に
  入れ、今の鳴動が終わった順に続けて鳴らす（以前は後から来たアラームに上書き
  されて先の方が鳴らず、履歴にも「鳴動」と残っていた）。待ちアラームの次回分の
  先行予約とスキップ整理は到着時点で行い、履歴の「鳴動」は実際に鳴り始めた
  時点で記録する。スヌーズして空いた場合も次の待ちアラームが鳴り始める
- 1回だけアラームは鳴り終わったら自動でオフになる（日付指定・日付なし共通）：
  鳴動終了時（停止・自動停止・スヌーズ上限到達時）に DB を無効化し、鳴動開始時に
  先行予約された翌日分も取り消す。スヌーズ中はオフにならず、スヌーズの再鳴動が
  終わった時点でオフになる。以前は日付なしの1回だけが翌日も鳴り続けていた
- 日付指定の1回だけアラームを追加：繰り返しメニューの「日付を指定（1回だけ）」
  からカレンダーで日を選ぶと、その日だけ鳴る。曜日指定とは排他で、過去の日は
  選べない。その日がグループの休日オフに当たると鳴らない（次回なし扱い）
- バックアップを追加：「設定・許可」画面からアラーム・グループ・カスタム休日を
  JSONファイルに書き出し／読み込みできる。読み込みは現在のデータを全て置き換える
  方式（IDはファイルの値をそのまま使うため所属関係は崩れない）。鳴動履歴は対象外
- 鳴動履歴を追加：一覧右上の履歴アイコンから「鳴動／スヌーズで再鳴動／
  スヌーズ（○分後）／停止／自動停止」を新しい順に最大200件確認できる。
  履歴は鳴動時点のラベル・時刻のスナップショットで、元アラームを消しても残る
  （DB v4、Migration でテーブル追加のみ・既存データ保持）
- 編集画面の繰り返し・グループも「選択ボタン→メニュー」方式に統一：
  繰り返しは要約表示（平日／毎日／月・水・金／1回だけ等）＋選択ボタンで、
  メニュー内はプリセット（毎日・平日・週末・1回だけ）と曜日のチェックボックス、
  「決定」で確定。グループは要約表示＋選択ボタンで、メニュー内は単一選択
- 音量の試し聴きを追加：ボイス音量には「ボイスをこの音量で試し聴き」
  （サンプル文をその音量で読み上げ）、SE音量には「SEをこの音量で試し聴き」
  （選択中の音源をその音量でループ再生。再生中のスライダー操作に音量が追従）
- 時刻・音量・スヌーズも「選択ボタン→メニュー」方式に統一（最終形）：
  編集画面の各カードは要約表示＋「選択」ボタンだけになり、実際の設定は
  すべてメニュー（ダイアログ）内で下書きを編集して「決定」で確定する。
  時刻は専用数字キーパッド、ボイス/SE音量はスライダー＋試し聴き
  （SE試し聴きはメニューを閉じると必ず止まる）、スヌーズは間隔・最大回数の
  2フィールド＋要約表示（例：「5分ごと・回数無制限」）。フェードインと
  バイブレーションだけはオン/オフ切替なのでカード内のスイッチのまま
- 次回/スキップまわりの領域は常時表示に統一：次回がない場合はサマリーカードに
  「次回はありません」、各カードには「スキップ予約なし」の行と押せない状態の
  「次回をスキップ」「スキップを全て取り消す」ボタンを残し、状態が変わっても
  カードの高さ・レイアウトが動かないようにした（ウィジェットのラベル行も同様）

## 既知の簡略化

- SE の音源は、編集画面の「選択」ボタンから開くメニューでカテゴリ別に選ぶ方式：
  内蔵音源（デフォルト＋ビープ／ベル／電子音、res/raw の合成 WAV）、着信音、
  アラーム音、通知音（いずれも端末の RingtoneManager から取得）、音楽ファイル
  （Storage Access Framework 経由で読み取り許可を永続化するため、再起動後も
  鳴動サービスから再生できます。元ファイルを移動・削除すると SE は鳴らず、
  ボイスのみになります）。メニューの各音源には試し聴きの再生／停止ボタンがあり、
  選ぶ前にその場で音を確認できます（アラーム用途の属性でループ再生）
- ウィジェットは Glance ではなく RemoteViews 採用です（確実に動作させるため）
- 鳴動中は次回分を先にスケジュールする方式のため、鳴動画面で停止しても次回は保持されます
